# Konfiguracja karty dźwiękowej WM8960 dla strumieniowania głosu Rider-Pi

Ten przewodnik opisuje konfigurację karty dźwiękowej WM8960 dla niezawodnego dupleksowego strumieniowania audio (przechwytywanie + odtwarzanie jednocześnie).

## Konfiguracja ALSA

### 1. Podstawowa konfiguracja

Skopiuj dostarczoną konfigurację ALSA, aby włączyć operację dupleksową:

```bash
cp docs/audio/wm8960.asoundrc ~/.asoundrc
```

Lub ręcznie utwórz `~/.asoundrc` z następującą zawartością:

```
# Dsnoop device for capture (shared input)
pcm.wm8960_in {
    type dsnoop
    ipc_key 1024
    slave {
        pcm "hw:wm8960soundcard,0"
        channels 2
        rate 16000
        format S16_LE
    }
}

# Dmix device for playback (shared output)  
pcm.wm8960_out {
    type dmix
    ipc_key 2048
    slave {
        pcm "hw:wm8960soundcard,0"
        rate 48000
        format S16_LE
        channels 2
    }
}

# Asymmetric default device
pcm.!default {
    type asym
    playback.pcm "wm8960_out"
    capture.pcm  "wm8960_in"
}

# Control device
ctl.!default {
    type hw
    card wm8960soundcard
}
```

### 2. Weryfikacja

Przetestuj konfigurację:

```bash
# Test odtwarzania
aplay -D wm8960_out /usr/share/sounds/alsa/Front_Center.wav

# Test przechwytywania (nagranie 3 sekundy)
arecord -D wm8960_in -d 3 -f S16_LE -r 16000 -c 2 test.wav

# Test jednoczesnego dupleksu
arecord -D wm8960_in -f S16_LE -r 16000 -c 2 | aplay -D wm8960_out -f S16_LE -r 48000
```

## Wykorzystanie strumieniowania głosu

### Szybki start

```bash
# Zabij konfliktujące procesy
make voice-kill

# Pojedyncza interakcja
make voice-stream-once

# Ciągły tryb PTT (push-to-talk)
make voice-stream-listen
```

### Ręczne komendy

```bash
# Konfiguracja środowiska
export OPENAI_API_KEY="your-api-key-here"

# Pojedyncza interakcja strumieniowa
python3 -m apps.voice.cli once --mode stream \
  --capture device=wm8960_in sample_rate=16000 channels=2 \
  --playback device=wm8960_out

# Strumieniowanie push-to-talk
python3 -m apps.voice.cli ptt --mode stream \
  --capture device=wm8960_in sample_rate=16000 channels=2 \
  --playback device=wm8960_out
```

## Konfiguracja

System strumieniowania głosu jest konfigurowany przez `config/voice.toml`:

### Kluczowe ustawienia

```toml
[capture]
device = "wm8960_in"        # Używa aliasu dsnoop
sample_rate = 16000         # Wymagane dla OpenAI Realtime API
channels = 2                # Sprzętowe stereo, zmiksowane do mono

[playback]
alsa_device = "wm8960_out"  # Używa aliasu dmix
volume = 100

[service]
beep = true                 # Dźwięk zwrotny PTT
```

### Przetwarzanie audio

System automatycznie:
- Konwertuje wejście stereo na mono używając `audioop.tomono()`
- Zapewnia częstotliwość próbkowania 16kHz dla zgodności z API
- Loguje konwersję kanałów: `ch_in=2, ch_out=1`

## Rozwiązywanie problemów

### Brak wyjścia audio
1. Sprawdź dostępność urządzenia: `aplay -l | grep wm8960`
2. Przetestuj bezpośrednie odtwarzanie: `aplay -D wm8960_out test.wav`
3. Zweryfikuj głośność: `amixer -c wm8960soundcard`

### Problemy z przechwytywaniem
1. Sprawdź uprawnienia: `ls -l /dev/snd/`
2. Przetestuj przechwytywanie: `arecord -D wm8960_in -d 2 test.wav`
3. Zabij konkurujące procesy: `make voice-kill`

### Urządzenie ALSA zajęte
```bash
# Znajdź procesy używające urządzeń audio
lsof /dev/snd/*

# Zabij procesy audio
make voice-kill

# Zresetuj stan ALSA
alsactl init
```

### "Cisza po commit" (Silence After Commit)

To wskazuje, że wysłano audio stereo zamiast mono. Sprawdź logi dla:
```
event=stream.tx data={"ch_in": 2, "ch_out": 1, "sr": 16000}
```

Jeśli `ch_out` nie wynosi 1, miksowanie nie powiodło się.

### Błędy WebSocket SSL

Szukaj prawidłowych logów zamknięcia:
```
event=ws.closing data={"session_id": "..."}  
event=ws.closed data={"session_id": "..."}
```

Brak ich wskazuje nieprawidłowe zamknięcie WebSocket.

## Uwagi dotyczące wydajności

- **Częstotliwość przechwytywania**: 16kHz dla zgodności z API
- **Częstotliwość odtwarzania**: 48kHz dla stabilności sprzętu
- **Rozmiar chunka**: 20ms dla niskiego opóźnienia
- **Format**: S16_LE (16-bit signed, little-endian)

## Integracja z systemd

Dla wdrożenia produkcyjnego wyłącz konfliktujące usługi audio:

```bash
# Wyłącz PulseAudio (jeśli obecny)
systemctl --user stop pulseaudio
systemctl --user disable pulseaudio

# Użyj ALSA bezpośrednio
systemctl --user enable alsa-state
```

To zapewnia czysty dostęp sprzętowy ALSA dla strumieniowania dupleksowego.
